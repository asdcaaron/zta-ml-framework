## Overview

This project implements a **Risk-Adaptive Zero Trust Architecture (ZTA)** that combines two complementary machine learning layers for real-time network anomaly detection in hybrid workforce environments:

| Layer | Model | Type | Purpose |
|---|---|---|---|
| Layer 1 | **CNN-GRU** | Supervised | Classifies known attacks: DoS, Probe, R2L, U2R |
| Layer 2 | **Autoencoder** | Self-Supervised | Detects unknown/zero-day anomalies without labels |

The dual-layer output feeds a **risk score (0–1)** into the ZTA policy engine, which enforces access decisions in real time.

The framework is evaluated in a four-way comparison:

| System | Description |
|---|---|
| **A — Legacy VPN** | Traditional OpenVPN perimeter-based security |
| **B — ZTA Only** | Zero Trust access control, no ML |
| **C — ZTA + CNN-GRU** | Zero Trust + supervised attack classifier |
| **D — ZTA + Autoencoder** | Zero Trust + self-supervised anomaly detector |

## Why Two Models?

```
SUPERVISED (CNN-GRU)            SELF-SUPERVISED (Autoencoder)
────────────────────            ──────────────────────────────
Needs labelled data             Trains on normal traffic only
Classifies known attack types   Detects ANY deviation from normal
Strong on DoS, Probe            Catches zero-day / novel attacks
High precision on known threats Low false positives on normal traffic
```

Together they cover what neither can do alone:
- CNN-GRU catches **what we know**
- Autoencoder catches **what we don't know**

## Quick Start

### 1. Install dependencies

```powershell
cd "c:\Users\AARON\Desktop\New folder\zta-ml-framework"
pip install -r requirements.txt
```

### 2. Download NSL-KDD dataset

Download from the University of New Brunswick:
- https://www.unb.ca/cic/datasets/nsl.html

Place in `data/`:
- `data/NSL_KDD_Train.csv`
- `data/NSL_KDD_Test.csv`

### 3. Train both models

```powershell
# Train CNN-GRU (supervised) + Autoencoder (self-supervised)
python src/train.py

# Train CNN-GRU only (skip autoencoder)
python src/train.py --skip-ae
```

Training output:
```

STEP 2: Building CNN-GRU Model  (327K parameters)
STEP 3: Training CNN-GRU        (up to 50 epochs, class weights)
STEP 4: CNN-GRU Evaluation      (classification report)
STEP 5: Autoencoder Training    (normal traffic only — self-supervised)
STEP 6: Autoencoder Evaluation  (reconstruction error analysis)
```

### 4. Run four-way comparison

```powershell
python src/evaluate.py
```

### 5. Start the risk-scoring API

```powershell
python src/api.py
# Open http://127.0.0.1:5000 in your browser
```

### 6. Run Zeek traffic capture (Docker)

```powershell

python src/zeek_capture.py --mode log --file data/logs/conn.log
```

## Model Details

### CNN-GRU (Supervised — Layer 1)

| Component | Detail |
|---|---|
| Input | 40 NSL-KDD features (after noise removal) |
| Architecture | Conv1D(64→128→256) + GRU(128→64) + Dense(128→64→5) |
| Parameters | 327,685 (1.25 MB) |
| Output | 5-class softmax: Normal, DoS, Probe, R2L, U2R |
| Training data | All 125,973 labelled samples with class weighting |
| Test accuracy | ~76–78% |

### Autoencoder (Self-Supervised — Layer 2)

| Component | Detail |
|---|---|
| Input | 40 features (flattened) |
| Architecture | Encoder: 40→128→64→32→16 | Decoder: 16→32→64→128→40 |
| Parameters | ~55,000 |
| Output | Reconstruction error (MSE) |
| Training data | **Normal traffic only** — 67,343 samples, no labels used |
| Threshold | 95th percentile of normal reconstruction errors |
| Anomaly rule | error > threshold → ANOMALY flagged |

## Dataset Noise Handling

The NSL-KDD dataset had the following issues addressed before training:

| Issue | Detail | Fix |
|---|---|---|
| Zero-variance feature | `num_outbound_cmds` = 0 for all samples | Dropped (40 features remain) |
| Extreme outliers | `src_bytes` max=1.38B vs mean=45K | `log1p()` applied before MinMax |
| Class imbalance | U2R: 52 samples (0.04%) | `class_weight='balanced'` |
| Zero missing values | Confirmed clean | No imputation needed |

## API Reference

### `POST /predict`
Score a single traffic connection.

**Request:**
```json
{
  "features": {
    "duration": 0, "protocol_type": "tcp",
    "service": "http", "flag": "SF",
    "src_bytes": 232, "dst_bytes": 8153
  }
}
```

**Response:**
```json
{
  "risk_score": 0.12,
  "classification": "Normal",
  "confidence": 0.88,
  "action": "ALLOW",
  "latency_ms": 3.4
}
```

### Risk Score → ZTA Action

| Risk Score | Action | Meaning |
|---|---|---|
| > 0.8 | **BLOCK** | High confidence attack — session terminated |
| 0.5 – 0.8 | **CHALLENGE_MFA** | Suspicious — re-authentication required |
| 0.3 – 0.5 | **MONITOR** | Anomalous — flagged and watched |
| < 0.3 | **ALLOW** | Normal traffic — permitted |
