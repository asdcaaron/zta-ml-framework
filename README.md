## Overview

This project implements a hybrid cybersecurity framework that integrates **Zero Trust Architecture (ZTA)** with a **CNN-GRU machine learning model** for real-time network anomaly detection.

The framework is evaluated against two baselines in a three-way comparison:

| System | Description |
|---|---|
| **System A — Legacy VPN** | Traditional OpenVPN perimeter-based security |
| **System B — ZTA Only** | Zero Trust access control without ML |
| **System C — ZTA + ML (Proposed)** | Zero Trust + CNN-GRU anomaly detection |

## System Architecture

```
User/Device Request
       │
       ▼
┌─────────────────────┐
│  ZTA Access Control │  ← Keycloak MFA + device posture check
│  Layer              │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  Network Monitoring │  ← Zeek captures traffic features
│  Layer              │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  ML Detection Layer │  ← CNN-GRU scores risk (0–1)
│  Flask API :5000    │
└──────────┬──────────┘
           │
    ┌──────┴──────┐
    │  Risk Score │
    │  0.0 – 1.0  │
    └──────┬──────┘
           │
    ┌──────▼──────────────────────────────┐
    │  > 0.8  → BLOCK                     │
    │  0.5–0.8 → CHALLENGE MFA            │
    │  0.3–0.5 → MONITOR                  │
    │  < 0.3  → ALLOW                     │
    └─────────────────────────────────────┘
```

## Quick Start

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Download the NSL-KDD dataset

Download from the University of New Brunswick:
- https://www.unb.ca/cic/datasets/nsl.html

Place files in the `data/` folder:
- `data/NSL_KDD_Train.csv`
- `data/NSL_KDD_Test.csv`

### 3. Preprocess and train the model

```bash
python src/train.py
```

This will:
- Preprocess the NSL-KDD dataset
- Train the CNN-GRU model for up to 50 epochs
- Save the best model to `data/cnn_gru_model.h5`
- Output training curves to `data/training_curves.png`
- Print a full classification report

### 4. Start the risk scoring API

```bash
python src/api.py
```

The API will be available at `http://localhost:5000`

Test it:
```bash
curl -X GET http://localhost:5000/health
```

### 5. Run the three-way comparison evaluation

```bash
python src/evaluate.py
```

Results are saved to `data/results/`:
- `comparison_results.csv` — full metrics table
- `comparison_bar.png` — bar chart
- `confusion_matrices.png` — confusion matrices
- `summary.json` — JSON summary

### 6. Open the analysis notebook

```bash
jupyter notebook notebooks/analysis.ipynb
```

## Model Architecture — CNN-GRU

```
Input (41 NSL-KDD features)
    │
    ├── Conv1D(64)  + BatchNorm + Dropout
    ├── Conv1D(128) + BatchNorm + MaxPool + Dropout
    ├── Conv1D(256) + BatchNorm + Dropout
    │
    ├── GRU(128, return_sequences=True) + Dropout
    ├── GRU(64,  return_sequences=False) + Dropout
    │
    ├── Dense(128, relu)
    ├── Dense(64,  relu)
    └── Dense(5,   softmax)
         │
         ├── 0: Normal
         ├── 1: DoS
         ├── 2: Probe
         ├── 3: R2L
         └── 4: U2R
```

## API Reference

### `POST /predict`

Score a single network connection.

**Request:**
```json
{
  "features": {
    "duration": 0,
    "protocol_type": "tcp",
    "service": "http",
    "flag": "SF",
    "src_bytes": 232,
    "dst_bytes": 8153
  }
}
```

**Response:**
```json
{
  "risk_score": 0.12,
  "classification": "Normal",
  "confidence": 0.88,
  "action": "ALLOW",
  "latency_ms": 3.4,
  "probabilities": {
    "Normal": 0.88,
    "DoS": 0.05,
    "Probe": 0.04,
    "R2L": 0.02,
    "U2R": 0.01
  }
}
```

### `GET /health`
Returns API and model status.

### `GET /model/info`
Returns model metadata and current risk thresholds.

### `POST /predict/batch`
Score multiple connections in one request.

## Evaluation Metrics

| Metric | Description |
|---|---|
| Accuracy | Correct classifications / total |
| Precision | TP / (TP + FP) |
| Recall (TPR) | TP / (TP + FN) |
| F1 Score | Harmonic mean of precision and recall |
| False Positive Rate | FP / (FP + TN) — should be minimised |
| Response Time | Seconds from detection to enforcement |
